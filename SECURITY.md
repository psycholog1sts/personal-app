# Security Policy

## Reporting a vulnerability

Please do not put credentials, access tokens, private repository contents, personal data, or sensitive exploit details in a public GitHub issue.

Start from the repository **Security** tab and use GitHub private vulnerability reporting when that option is available. If the private reporting flow is not available, open a minimal public issue that contains no secret or exploit detail and asks for a private follow-up channel.

Repository security page: https://github.com/psycholog1sts/personal-app/security

## Scope

Useful reports include vulnerabilities in the RLSProof browser Quick Scan, CLI, GitHub Action, report handling, static-site code, or release-gate logic. Reports about third-party services should be sent to the relevant provider unless the issue is caused by RLSProof integration code.

## Safe reporting

Do not test against systems, repositories, databases, or accounts you are not authorized to assess. Do not run destructive database proof fixtures against production environments. Include the smallest reproduction necessary and redact secret material.

## What to expect

RLSProof is an independent software product under active development. A report being accepted does not imply a security certification, bounty program, or guaranteed response time. Valid reports will be evaluated against the current documented product behavior and security boundaries.
